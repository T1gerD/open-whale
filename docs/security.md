# 安全模型

本文说明 Open Whale 信任什么、不信任什么，以及攻击者能做什么、做不到什么。**没有经过验证的安全声明不会写在这里**；未验证的一律标注。

## 一句话模型

> 二维码只用来**首次建立信任**；建立之后，手机靠**自己保管的私钥**证明身份，电脑靠**自己的长期密钥**证明身份。中继（隧道、局域网、未来的自建服务器）**不被信任**。

## 身份与密钥

| 角色 | 密钥 | 存放位置 | 用途 |
|---|---|---|---|
| 电脑 | Ed25519 长期密钥对 | `$DSH_HOME/openwhale/state.json`（0600） | 签名 `hello/ack`，证明"我是你绑定的那台电脑" |
| 手机 | Ed25519 设备密钥对 | 手机系统安全存储（私钥**从不上传**） | 签名每次重连的握手，证明"我是那台被绑定的手机" |
| 二者之间 | 一次性配对密钥（≥128 位随机） | 只存在于二维码与 10 分钟窗口内 | 首次绑定授权 |

指纹：电脑公钥的 SHA-256（十六进制），在二维码、绑定页面、手机端三处显示，供人工比对。

## 绑定流程（首次）

1. 电脑生成**一次性**配对密钥（10 分钟有效），连同电脑 ID、公钥指纹、**电脑公钥**、可用地址一起编码进二维码。
2. 手机扫码后：
   - 校验载荷结构与有效期（过期即拒绝）；
   - 生成自己的设备密钥对；
   - 连接二维码里的地址，首帧发 `hello`，带上设备公钥、随机 nonce 和配对密钥。
3. 电脑：
   - 先做**单手机约束检查**：若已绑定别的手机，直接拒绝（哪怕配对密钥正确）；
   - 再校验配对密钥，**一次性消费**（用过/过期/不匹配都拒绝）；
   - 绑定成功，返回 `hello/ack`，其中包含对 `helloAckProofMessage(nonce, deviceId)` 的签名。

## 重连流程（日常）

1. 电脑连接建立时无需预先发放任何东西。
2. 手机发 `hello`，带**自己选的** nonce 与对 `openwhale-hello:<nonce>` 的签名。
3. 电脑用**已绑定记录里的公钥**验签，并用随机数防重放表拒绝重复 nonce。
4. 电脑回 `hello/ack`，签名内容为 `openwhale-hello-ack:<nonce>:<deviceId>`。

> 为什么 nonce 由客户端选：客户端必须在自己还没收到任何可信输入之前就有东西可签；时间戳不可信，所以**防重放靠服务端记住用过的 nonce**，而不是靠客户端报时。

## 攻击面与对策

| 攻击 | 结果 | 原因 |
|---|---|---|
| 二维码被拍照外发 | **有限**：仅能在 10 分钟窗口内、且电脑尚未绑定时使用 | 一次性密钥 + 单手机约束 |
| 二维码在绑定时被中间人截获并抢先绑定 | 抢先者成功，原用户失败 | 这是首绑的固有窗口，也是为什么二维码窗口短、且应在可信网络下完成 |
| 隧道域名被冒名顶替 | **可被发现**：手机用二维码里的电脑公钥验 `hello/ack` 签名，验证失败即拒绝 | 二维码携带 `pk` |
| 重放捕获到的 `hello` | 拒绝 | nonce 防重放表（10 分钟窗口、每设备有上限） |
| 攻击者知道 deviceId 但没有私钥 | 拒绝（`bad-signature`） | 认证只认私钥签名 |
| 已绑定手机伪造另一台设备 | 拒绝 | 电脑记录里只有已绑定设备的公钥 |
| 手机请求电脑上任意文件 | 拒绝 | 只登记并允许拉取**本次对话中产出**的文件 |
| 手机刷屏 / 超大消息 | 有上限：单消息 100k 字符、单附件 32 MiB、单文件 512 MiB、帧 8 MiB、消息 16 MiB | 传输层与网关双重限制 |
| 下载链接被转发 | 有限：单次使用、5 分钟有效 | 一次性下载令牌 |
| 电脑端状态文件被本地其他程序读取 | 取决于操作系统账户隔离 | 文件以 0600 写入；Windows 上 POSIX 权限位不生效，依赖用户目录 ACL |

## 加密：做了什么，没做什么

- **传输加密**：局域网模式是明文 HTTP/WebSocket（同网段信任）；公网模式依赖隧道提供的 TLS（`https://`/`wss://`）。
- **应用层加密：目前没有做端到端加密。** 这意味着**隧道提供方（例如 Cloudflare）在技术上可以看到流量内容**。如果你不接受这一点，请使用自建隧道或不暴露到公网。
  - 协议已按「中继不可信」设计（身份验证与鉴权都在应用层，与前缀无关），因此未来加入内容加密不需要改协议，但**当前版本没有实现**。
- 私钥从不通过网络传输；配对密钥会传输一次，但属于一次性短期凭据。

## 权限与危险动作

| 动作 | 默认 | 说明 |
|---|---|---|
| 关机 / 重启 | **允许**，30 秒可取消宽限窗口 | 可通过 `allowRemoteShutdown: false` 关闭；关闭后**取消仍然可用**（取消是安全方向，不应被锁掉） |
| 唤醒（WOL） | 允许发送 | 不阻断；受物理条件限制，见 [remote-power.md](remote-power.md) |
| 自动批准工具调用 | **关闭** | 关闭时手机发来的请求走 DSH 原有审批策略。开启后跳过审批，等于把电脑上执行命令/写文件的权力交给手机持有者，请自行权衡 |
| 读取文件 | 仅本次对话产出 | 不能指定任意路径 |

## 日志与隐私

- 电脑端日志会记录连接、绑定、解绑、隧道地址等事件；**不记录**配对密钥或私钥。
- 手机端的聊天内容与文件保存在手机的本地数据库（`expo-sqlite`）与安全存储中。
- 手机消息会进入 DSH 会话日志（与你在桌面上聊天一样），因此也会进入 DSH 自己的会话持久化路径。

## 已知限制（明确列出，避免误判）

1. **无端到端加密**（见上）。
2. 首次绑定的中间人窗口无法从协议上消除，只能靠短有效期与单手机约束收窄。
3. 快速隧道由第三方运营，其可用性、域名稳定性与隐私政策不在本项目控制内。
4. 电脑上的 `state.json` 若被同一账户下的其他程序读取，攻击者可以获得电脑私钥（可用于冒充电脑），但仍**不能**冒充手机（手机私钥在手机上）。此时应立即解绑并重新生成身份。
5. 手机端应用**尚未在真机做过安全测试**（本仓库开发环境无 Android SDK）。密码学原语使用 `tweetnacl`；纯逻辑层有单测覆盖，但真机行为（安全存储、SQLite 加密状态）未验证。
6. 关机权限：非交互会话（服务/计划任务/远程会话）可能缺少 `SeShutdownPrivilege` 而失败，见 [remote-power.md](remote-power.md)。

## 如果你想更保守

- 不开公网隧道，只用局域网；
- `allowRemoteShutdown: false`；
- `autoApproveTools: false`（默认）；
- 只用一台设备绑定，并定期检查 `/openwhale/health` 的 `devices` 列表；
- 不用时从手机端解绑，或在电脑端删除 `$DSH_HOME/openwhale/state.json` 并重启 DSH。
