# 架构

## 总览

```
┌──────────────┐        ┌───────────────────┐        ┌──────────────────────┐
│   手机 App   │◀──────▶│   DSH 插件        │◀──────▶│  DeepSeek Harness    │
│              │  WSS   │  gateway + bridge │  会话  │  模型 + 工具调用     │
└──────────────┘        └───────────────────┘        └──────────────────────┘
```

- **手机 App**：只负责交互与传输（配对、签名、UI、离线队列）
- **插件 gateway**：负责鉴权、连接管理、路由
- **插件 bridge**：为每台手机维护一个 DSH 会话，把消息转成 Agent 输入，把事件流打回手机

---

## 通路

手机保存多个候选地址，按优先级选择：

| 优先级 | 通路 | 说明 |
|---|---|---|
| 1 | 公网隧道（`https://` / `wss://`） | 任意网络可用，包括移动数据 |
| 2 | 局域网直连（`http://192.168.x.x`） | 同一网络且无客户端隔离时可用 |
| 3 | USB 调试通道（`http://127.0.0.1`） | 经 `adb reverse`，用于应急与内部测试 |

规则：**一旦某地址连接成功就锁定它**，只有连续失败到阈值才切换下一个。
这样避免了在"部分地址不可达"的网络里刚连上就被切走。

## 协议

WebSocket 端点为 `/openwhale/ws`，帧为 JSON。

### 握手

```
手机 → 电脑   { "t": "hello", "deviceId", "devicePublicKey", "nonce", "signature" | "pairSecret" }
电脑 → 手机   { "t": "hello/ack", "version", "computerId", "fingerprint", "heartbeatMs", "endpoints" }
```

- 首次绑定：携带 `pairSecret`（单次、10 分钟有效）
- 之后每次：用设备私钥对 `nonce` 签名
- `hello/ack` 里会下发电脑当前可用的地址列表，手机据此更新本地记录

### 消息

| 帧 | 方向 | 用途 |
|---|---|---|
| `chat/send` | 手机 → 电脑 | 发送用户消息（`rid` 作为幂等键） |
| `chat/ack` | 电脑 → 手机 | 已接管该消息，手机可出队 |
| `chat/delta` | 电脑 → 手机 | 增量文本 |
| `chat/typing` | 电脑 → 手机 | 处理中提示 |
| `chat/done` | 电脑 → 手机 | 本轮结束 |
| `chat/error` | 电脑 → 手机 | 错误（含 `retryable`） |
| `ping` / `pong` | 双向 | 心跳 |

## 离线队列

移动网络必然断续，因此手机端维护一个持久化待发队列：

- 消息先入队，再尝试发送
- 收到 `chat/ack` 才出队
- 断线时把"已发出但未确认"的条目退回待发，重连后按入队顺序重发
- 重试有次数上限，超出后由用户手动重试

## 安全模型

| 风险 | 对策 |
|---|---|
| 配对载荷被截获 | 单次密钥 + 10 分钟过期 + 电脑指纹校验 |
| 设备被冒充 | 每次连接对服务端 `nonce` 做 Ed25519 签名 |
| 私钥泄露 | 私钥保存在系统安全区，不出设备 |
| 电脑暴露面 | 只主动出站，不开放入站端口 |
| 多设备抢占 | 一台电脑绑定一台手机，重复绑定直接拒绝 |

## 依赖策略

插件侧刻意保持**零运行时依赖**：

- WebSocket 服务端自研（`packages/plugin/src/ws.mjs`）
- 二维码编码自研，符合 ISO/IEC 18004（`packages/plugin/src/qr.mjs`）

原因是绑定二维码必须"装上就能用"——如果它依赖某个装不上的包，用户连第一步都走不完。
